1-2 変数とデータ型

← S03 スライド図再現
変数（variable） プログラム中でデータを一時的に記憶しておく仕組み。メモリ内の領域に名前をつけ、代入などによってデータを格納できるようにしたもの。プログラム中では格納値に置き換えられて実行される。← S03

主なデータ型 ← S03

データ型英語名説明補足

1-3 データ構造（1）― 配列・レコード

← S03:p15 スライド図再現
配列（array） 同じ種類のデータを連続して並べた構造。配列内の各データは要素と呼ばれ、要素番号（添え字）により区別する。添え字は多くの言語で0から始まる。← S03
レコード（record） 異なる種類のデータを1件にまとめた構造（表の1行分に相当）。レコード内の各項目をフィールドという（表の列に相当）。← S03

1-4 データ構造（2）― リスト・木構造

← S03:p18 スライド図再現
リスト（連結リスト / linked list） 各データに「次のデータの格納位置」を示すポインタを付加し、論理的に繋げた構造。配列を含む広義の「リスト」と区別して「連結リスト」ともよばれる。← S03
木構造（tree） データを下へ向かって伸びる木のように繋げた構造。各部分はノード（節）と呼ばれ、最上位を根（root）、最下位を葉（leaf）という。上下関係は親・子で表す。全ノードの子が2つ以下を二分木（binary tree）という。← S03

1-6 構造化プログラミングと3つの基本構造

← S03:p30 スライド図再現
構造化プログラミング エドガー・W・ダイクストラ（Edgar W. Dijkstra）らが1960年代に提唱。プログラムを3つの基本構造の組み合わせで作ることで、バグが少なく改修・保守・再利用のしやすいプログラムを実現する考え方。← S03:p30
基本構造別名説明
順次逐次実行処理を上から順番に1つずつ実行する
選択分岐条件式の真偽などによって処理の流れを変える
繰り返し反復・ループ条件が満たされる間、同じ処理を繰り返す

各構造は「入口」と「出口」が1つずつのため自由に組み合わせられる。← S03

1-7 アルゴリズムの表現方法

← S03:p41 スライド図再現

フローチャートは「流れ図」とも呼ばれ、JIS X0128（対応国際規格: ISO 8631）で規格化された記号と線でアルゴリズムを図式化したもの。線の流れは原則として上から下、左から右へ向かい、それ以外の場合は線の先に矢先（矢印）をつける。← S03:p41,42

擬似言語（擬似コード）は規格がなく、プログラミング言語に近い形式でアルゴリズムを記述する。制御構文: if/endif・while/endwhile・for/endfor。分岐・繰り返しの範囲はインデント（字下げ）がマナー。注釈: /* 注釈 */（複数行）・// 注釈（行末まで）。代入記号: ← を使う書き方も広く使われる。← S03:p44-46

2-3 二分探索（バイナリサーチ）

← S03:p70 スライド図再現
二分探索（バイナリサーチ / Binary Search） データが昇順（または降順）に整列済みであることを前提に、検索範囲の真ん中の要素と目標を比べ、大小によって検索範囲を半分ずつ絞っていく方法。速い。
フローチャートのポイント: 初期値 左端←1, 右端←8。中 ← (左端+右端)/2（小数点以下切り捨て）。終了条件: 左端 > 右端 なら「見つからなかった」。← S03:p70
線形探索二分探索
事前整列不要必要（昇順/降順）
速度遅い（最悪: 全件走査）速い（目標によらず短い）

並べ替えを行う理由 ← S03:p75

高速な二分探索を利用するためにはデータを順序良く並べておく必要がある。これが並べ替え（整列・ソート）の主要な動機のひとつ。

並べ替えの規則 ← S03:p75

  • 文字列: 五十音順・アルファベット順 ─ 内部的には 文字コード（数値）に従った並べ替え
  • 数値: 昇順（小→大）・降順（大→小）

多種のアルゴリズムが存在: バブルソート・選択ソート・クイックソートなど

2-4 バブルソート

← S03:p81,85 スライド図再現
/* バブルソート 擬似コード（S03:p90 完全再現） */ for( 右端 を n から2まで 1 ずつ減らす ) for( i を 1 から 右端-1 まで 1 ずつ増やす ) if( x[ i ] > x[ i+1 ] ) x[ i ] と x[ i+1 ] の 値を交換　← tmp ← x[i] / x[i] ← x[i+1] / x[i+1] ← tmp の3ステップ end if end for end for
バブルソート（Bubble Sort） 隣合う要素を比較し大小関係が違えば交換する処理を左端から右端まで繰り返す。1周するたびに最大値が右端へ確定するので、右端を除いた範囲で同じことを繰り返す。← S03
⚠️ 値の交換は必ず3ステップ
同時代入は不可。tmp（一時退避変数）で①退避→②上書き→③復元の手順が必須。← S03:p85

2-5 選択ソート（最大値選択法）

← S03:p92-94 スライド図再現
/* 選択ソート（最大値選択法）擬似コード（S03:p95 完全再現） */ for( 右端 を n から2まで 1 ずつ減らす ) 仮の最大 ← 右端　← まず右端を仮の最大値位置とする for( i を 1 から 右端-1 まで 1 ずつ増やす ) if( x[ i ] > x[仮の最大] ) 仮の最大 ← i end if end for x[仮の最大] と x[右端] の 値を交換　← 1周に1回のみ end for
選択ソート（最大値選択法） 仮の最大を更新しながら範囲を1周して最大値を見つけ、右端と1回だけ交換する。右端を除いた1つ狭い範囲で繰り返す。← S03

※ 最大値選択法の他、最小値選択法なども含め「選択ソート」と総称する。← S03:p95脚注

2-6 クイックソート

← S03:p100-102 スライド図再現
クイックソート（Quick Sort） 基準値（ピボット）を決め、基準値以下と基準値以上のデータ列に分割する処理を、分割後の各データ列に対しても再帰的に繰り返す。全データが1つずつになったら完了。
分割処理の詳細: データ列の両端から内側へ向かい、左から右へと調べて基準値以上のデータを探し、右から左へと調べて基準値以下のデータを探して交換。見つけた位置が一致または逆転したら分割終了。← S03:p102
📗 外部補足: 計算量
バブルソート・選択ソートはO(n²)、クイックソートは平均O(n log n)。nが大きいほど差が顕著になる。[外部補足: アルゴリズム教科書]

第3章 プログラムの性質

プログラミングとは、プログラミング言語を用いてアルゴリズムを記述すること。コンピュータは人間のような柔軟な解釈ができないため、指示は曖昧さのない正確なものでなければならない。本章はJavaScriptを用いて3例で性質を学ぶ。

🎤 音声補足（田中先生）
「塩を適量」ではコンピュータは何もできないが「塩を3g加える」なら正確に処理できる。プログラミング未経験者でもOK。実際に動かすことを推奨——試行錯誤してもコンピュータは壊れない。← S03 / S05-A

3-1 例（1）順次実行・分岐・繰り返し

① 順次実行 — 上から順番に1行ずつ実行

// 順次実行（S03:p113 再現） var 名前 = "歳三"; alert("こんにちは、" + 名前 + "さん！"); // 実行結果：「こんにちは、歳三さん！」

各文末の ; は文の区切り。// で始まる行はコメント（実行に影響しない）。行の順番を入れ替えると意図しない動作になる。← S03

② 分岐（if文）— 条件に応じて処理の流れを変える

// 分岐（if文） var 年齢 = 18; if (年齢 >= 18) { alert("あなたは成人です。"); } else { alert("あなたは未成年です。"); } // 年齢>=18 が真 → 「あなたは成人です。」

比較演算子（>=等）で条件を記述。2方向だけでなく3方向以上に分岐させることも可能。← S03

③ 繰り返し（for文）— S03:p120 スライド再現

// 繰り返し（for文） for (var 回数 = 1; 回数 <= 5; 回数=回数+1) { alert("カウント：" + 回数); } // 実行結果：「カウント：1」〜「カウント：5」が順に表示

for文の 「初期値・条件式・更新」 の3点セットが重要。回数が決まっていない繰り返しは while文 / do～while文 で表現。← S03:p120

⚠️ 無限ループに注意
「初期値・条件式・更新」の設定を間違えると、繰り返しが終わらない無限ループが発生してプログラムが止まらなくなる。← S03

3-2 例（2）データ型・配列・オブジェクト

← S03:p130 スライド再現
⚠️ + 演算子の二重性
加算演算子（+）は数値どうしなら「足し算」、文字列との組み合わせでは「文字列の連結」になる（予期せぬ連結に注意）。また文字列を囲むダブルクオート（"）の閉じ忘れは典型的なバグ。← S03:p130
// 数値型：四則演算が可能 var 得点 = 85; var 新得点 = 得点 + 10; // → 95 // 文字列型：+ で連結 var 名前 = "花子"; var 挨拶 = "こんにちは、" + 名前 + "さん！"; // →「こんにちは、花子さん！」 // 配列：添え字は0から始まる var 果物 = ["りんご", "バナナ", "オレンジ"]; alert(果物[0]); // → 「りんご」 // オブジェクト：ドット記法でプロパティにアクセス（S03:p130 再現） var 人物 = { 名前: "総司", 年齢: 30, 職業: "庭師" }; alert(人物.名前 + "さんは" + 人物.職業 + "で、" + 人物.年齢 + "歳です。"); // 「総司さんは庭師で、30歳です。」 人物.職業 = "教師"; // プロパティを変更 alert(人物.名前 + "さんの職業は" + 人物.職業 + "になりました。");

← S03:p130

⚠️ 注意点
  • + は数値加算にも文字列連結にも使う。本当に数値どうしを足しているかに気を付ける。← S03:p121
  • 文字列を囲むダブルクォート（"）の閉じ忘れに注意。← S03
  • 配列の添え字は0から始まる（0番が最初の要素）。間違った添え字で意図しない値が出ることがある。
  • 配列は繰り返し処理と組み合わせることで大量のデータ操作がスムーズに行える。← S03:p123
  • オブジェクトは通信やデータの入出力にも活用される。プロパティ値の変更は容易なため意図しない上書きに注意。← S03

3-3 例（3）オブジェクトの継承

← S03 スライド図再現
// 動物オブジェクトを定義 var 動物 = { 名前: "名前のない動物", 鳴き声: "...", 鳴く: function() { alert(this.名前 + "が" + this.鳴き声 + "と鳴く"); } }; // 犬型（動物を継承） var 犬 = Object.create(動物); 犬.鳴き声 = "ワン"; // ポチを生成して鳴かせる var ポチ = Object.create(犬); ポチ.名前 = "ポチ"; ポチ.鳴く(); // → 「ポチがワンと鳴く」

thisキーワードは呼び出し元のオブジェクト自身を指す。継承により動作（鳴く）を共有しながら固有の値（鳴き声）を上書き設定できる。← S03

継承（inheritance） 既存オブジェクトのプロパティや動作を新たなオブジェクトが引き継ぐ仕組み。共通部分を再利用しながら固有の設定を追加・変更できる（再利用性・拡張性の向上）。← S03

第4章 プログラミング言語とその他の言語

4-1 プログラミング言語の概要・分類

🎤 音声補足
コンパイル言語は「全体をまとめて一気に訳す（翻訳）」、インタプリタ言語は「1文ごとに同時通訳する」イメージ。← S05-A

プログラミング言語の概要 ← S03:p140

コンピュータに指示を与えるために人によって作られた人工言語。人間が理解しやすい形式で書けるよう設計されており、実行時には機械語に変換される。

基本要素: 文法（言語の規則・構造）・予約語（言語で特別な意味を持つ定義済みの単語、例: var if for）・変数・関数

ライブラリ（Library） 頻繁に使用する機能をまとめた再利用可能なプログラムの集まり。データ交換・乱数生成・統計処理・図形描画などを1から作らず呼び出すだけで使える。便利・労力を減らせる。← S03:p160

📚 補足B: 確認済み背景知識

  • Niklaus Wirth「Algorithms + Data Structures = Programs」
    スイスの計算機科学者 Niklaus Wirth（1934–2024）著。Prentice Hall, 1976年刊。スライド脚注に書誌情報が明記されている。[外部補足・確認済: S03:p10脚注]
  • エドガー・W・ダイクストラ（Edgar W. Dijkstra, 1930–2002）
    オランダの計算機科学者。1960年代に構造化プログラミングを提唱。最短経路アルゴリズム（ダイクストラ法）の考案者でもある。1972年 ACM チューリング賞受賞。[外部補足・確認済: ACM Turing Award記録]
  • Java の「Write Once, Run Anywhere（WORA）」
    JVM（Java Virtual Machine）がOSの差異を吸収するため、一度コンパイルしたJavaプログラムはJVMが動く環境ならどのOSでも実行できる原則。[外部補足・確認済: S03 / Sun Microsystems]
  • フローチャートのJIS規格
    JIS X0128「プログラム構成要素およびその表記法」、対応国際規格はISO 8631。スライド脚注に明記されている。[外部補足・確認済: S03:p41脚注]
  • YAML の名称の意味
    YAML = "YAML Ain't Markup Language"（再帰的頭字語）。名前にMarkup Languageを含むが実際はデータ記述方式。[外部補足・確認済: S03 / YAML公式仕様]
  • ソートアルゴリズムの計算量
    バブルソート・選択ソート: O(n²)。クイックソート: 平均O(n log n)、最悪O(n²)。二分探索: O(log n)、線形探索: O(n)。[外部補足: アルゴリズム教科書]

🔗 補足D: 関連概念・次回への接続

  • 計算量（オーダー記法）: 線形探索O(n)、二分探索O(log n)。バブル・選択O(n²)、クイックソート平均O(n log n)。[外部補足・確認済]
  • オブジェクト指向の4大概念: 本章の「継承」のほか、カプセル化（データの隠蔽）・ポリモーフィズム（多態性）・抽象化がOOPの基本原則。[外部補足・確認済]
  • 配列の添え字0始まりの理由: 多くの言語で先頭要素の添え字が0。これは「先頭からのオフセット（距離）」という設計で、C言語の仕様が多くの言語に影響を与えた。[外部補足・確認済]
